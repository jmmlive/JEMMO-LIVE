JEMMO LIVE V1 · ID PÚBLICA Y SEGURIDAD PRUEBA 08
Fecha: 25/07/2026

Base vigente:
- JEMMO LIVE V1 · PERFILES Y MENSAJES REALES PRUEBA 07.
- PRUEBA 07 validada entre Jesús y Ruth: perfil editable, búsqueda y mensajes bidireccionales reales.

Objetivo de esta entrega:
- Cerrar la base de identidad y mensajería antes de comenzar el módulo Chili IA.
- Sustituir el correo público por una ID JEMMO única, permanente y copiable.
- Proteger perfiles, conversaciones y mensajes mediante reglas autenticadas de Cloud Firestore.

ID pública JEMMO:
- Cada cuenta recibe automáticamente una ID con formato JEMMO-1000001, JEMMO-1000002, etc.
- La asignación utiliza una transacción Firestore con contador y reserva única para evitar duplicados.
- La ID pública es distinta del UID técnico de Firebase.
- La ID no cambia aunque se modifique el correo, el nombre, el dispositivo o la foto.
- Las cuentas existentes reciben su ID al iniciar sesión con esta revisión.
- El perfil propio sustituye la antigua ID local derivada del UID por la nueva ID pública.
- La ID aparece con acciones para copiar y compartir desde el perfil.

Privacidad y búsqueda:
- El correo queda reservado para acceso, verificación y recuperación de cuenta.
- El correo se elimina del directorio público de Mensajes durante la migración.
- La búsqueda pública admite ID JEMMO, nombre de usuario o nombre público exacto.
- Se elimina la búsqueda por correo y por UID técnico de Firebase.
- Los perfiles públicos ya no muestran el correo de acceso.

Mensajería:
- Las conversaciones directas utilizan un ID determinista formado por los dos UID ordenados, evitando duplicados.
- Se conserva el contador real de mensajes no leídos y el marcado como leído.
- La lista mantiene último mensaje, hora y orden por actividad.
- Los perfiles guardados dentro de una conversación ya no contienen correos.
- Solo se actualiza la copia del perfil correspondiente al usuario autenticado.

Seguridad entre usuarios:
- Se añade bloqueo y desbloqueo desde las opciones de una conversación.
- Un bloqueo impide enviar mensajes en ambos sentidos cuando se publican las reglas de PRUEBA 08.
- Se añade denuncia por spam, acoso, suplantación o posible menor.
- El perfil público permite bloquear, desbloquear o denunciar.
- Las denuncias se guardan en Firestore con estado pendiente para futura revisión administrativa.

Reglas Firestore:
- Archivo separado: JEMMO_LIVE_V1_PRUEBA_08_FIRESTORE.rules.
- Cada usuario solo puede leer y modificar su documento privado users/{uid}.
- El directorio público no admite campos email ni emailLower.
- Solo los participantes pueden leer una conversación y sus mensajes.
- Solo el remitente autenticado puede crear un mensaje con su propio UID.
- Los mensajes no pueden modificarse ni borrarse desde el cliente.
- Las IDs públicas se reservan de forma atómica y no pueden modificarse después.
- Los bloqueos solo pueden ser administrados por la persona que bloquea.
- Las denuncias solo pueden ser creadas por el usuario autenticado.
- Las colecciones antiguas de prueba quedan bloqueadas para escritura.

Prueba cruzada requerida:
1. Publicar los archivos del ZIP y las reglas Firestore.
2. Jesús inicia sesión y comprueba su nueva ID JEMMO.
3. Ruth inicia sesión y comprueba su nueva ID JEMMO.
4. Copiar y compartir ambas IDs.
5. Buscar por ID y por nombre de usuario, nunca por correo.
6. Enviar mensajes en ambos sentidos y verificar los contadores.
7. Bloquear, comprobar que el envío se rechaza y después desbloquear.
8. Enviar una denuncia de prueba y comprobar la colección denuncias.
9. Cerrar y abrir la aplicación para verificar persistencia.
